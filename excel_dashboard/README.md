# KIS PM Daily Dashboard (Excel + Power Query)

KOSPI·KOSDAQ 개별종목 모의투자(수익률·샤프지수 평가)를 운용역처럼 관리하기 위한 **일일 대시보드**입니다.
한국투자증권 Open API를 Excel Power Query가 직접 호출하며, 이 저장소 `examples_llm/`의 URL·tr_id·파라미터를 그대로 M 코드로 옮겼습니다.
**조회 전용**이며 주문 API는 쓰지 않습니다.

```
excel_dashboard/
├── KIS_PM_Dashboard.xlsx   # 생성된 통합문서 (git 제외 — 토큰 캐시·개인 매매기록 포함)
├── build_dashboard.py      # 통합문서 생성기 (Excel COM)
├── xl_helpers.py           # COM·서식·차트 헬퍼
└── powerquery/*.pq         # Power Query(M) 원본 — 통합문서 안의 쿼리와 동일
```

## 1. 준비

1. `~/KIS/config/kis_devlp.yaml`에 **실전투자** 앱키(`my_app`)·시크릿(`my_sec`)·도메인(`prod`)이 있어야 합니다(저장소 README 3.5절).
   시세·순위·수급 API는 모의투자 도메인에서 지원되지 않는 경우가 많아 실전 도메인으로 조회만 합니다.
2. Windows + Microsoft 365 Excel (LET·FILTER·SORTBY·TAKE·VSTACK·HSTACK·XLOOKUP 사용).
3. 통합문서를 다시 만들 때만 Python + `pywin32`, `pyyaml` 필요.

```powershell
python excel_dashboard/build_dashboard.py            # 샘플 매매일지·관심종목 포함
python excel_dashboard/build_dashboard.py --empty    # 빈 매매일지로 생성
python excel_dashboard/build_dashboard.py --cfg D:/my/kis_devlp.yaml
```

빌드는 별도의 숨김 Excel 인스턴스를 띄워 쿼리를 넣고 한 번 새로 고침한 뒤 저장합니다(약 2~3분). 열려 있는 다른 Excel 창에는 손대지 않습니다.

## 2. 처음 한 번

1. `KIS_PM_Dashboard.xlsx`를 열고 노란 보안 경고 줄이 뜨면 **[콘텐츠 사용]**. (‘웹 콘텐츠 액세스’ 창이 뜨면 **익명 → 연결**)
2. **[설정]** 시트: 대회 시작일·종료일·초기자금·수수료율·거래세율·벤치마크를 대회 규정대로 수정.
3. **[매매일지]**의 `[샘플]` 행과 [설정]의 샘플 관심종목을 지우고 내 것으로 바꿉니다. (표가 비었다 다시 채워져도 수식·서식은 유지됩니다)
4. **[데이터] > [모두 새로 고침]** (`Ctrl+Alt+F5`) — 약 20~40초.

## 3. 매일 루틴

| 시간 | 할 일 |
|---|---|
| 08:30 장 전 | 새로 고침 → [시장] 해외지수·환율·금리 → [대시보드] 알림(손절·목표·비중) → 오늘 계획 |
| 장중 | 필요할 때 새로 고침 → [시세판] 신호(거래량급증·52주고가근접·골든크로스) · [시장] 주도주·수급 |
| 매매 직후 | [매매일지]에 한 줄(매매근거 필수) → 새로 고침 |
| 15:40 장 후 | [성과] 샤프·MDD·초과수익 → [리스크] 위험기여 상위 종목 → 내일 계획 |

| 포트폴리오 | 보유종목: 평가손익·비중·일간손익·손절/목표 여유·RSI·이격도·변동성·베타·위험기여·수급·신호 |

## 5. 지표 정의

- **NAV(t)** = 초기자금 + 누적 현금흐름 + Σ 보유수량×종가(수정주가). 매매일지와 일봉으로 매일 재구성합니다(외부 입출금 없음 가정).
- **샤프** = (일간수익률 평균 − 무위험/252) ÷ 일간수익률 표준편차 × √252. 무위험수익률은 설정값 또는 CD91일물. rf=0 값도 함께 표시.
- **MDD** = 고점 대비 최대 하락률 · **알파** = 젠센 알파(연율화) · **정보비율** = 연 초과수익 ÷ 추적오차.
- **사전 변동성·위험기여** = 현재 비중을 최근 60영업일 수익률에 적용. 위험기여비중 합계 = 100%.
- 평균단가는 **매수 수수료 포함 원가** → 실현손익 + 평가손익 = 순자산 − 초기자금 이 정확히 일치합니다.

빌드 검증 시 샤프·변동성·MDD·누적수익률을 NAV 원장에서 Python으로 독립 재계산해 Excel 값과 소수점 4자리까지 일치함을 확인했습니다.

## 6. 데이터 흐름과 안정성

- **토큰**: `T_Token` 쿼리만 발급합니다(자기 결과표를 다시 읽는 캐시). 남은 유효시간이 3시간 미만일 때만 재발급 → 발급 시 KIS 알림톡 1건. 나머지 쿼리는 캐시된 토큰만 읽습니다(동시 발급으로 인한 `EGW00133`·알림톡 폭주 방지). 파일을 열 때와 30분마다 자동 확인.
- **호출 제한**: 초당 건수 초과(`EGW00201`)만 짧은 백오프로 최대 5회 재시도, 네트워크 오류는 1회, 설정·토큰 문제는 재시도 없이 즉시 실패.
- **실패 시**: 오류 대화상자 대신 **직전 데이터를 유지**하고 `상태` 열에 `이전 데이터(갱신 실패: 사유)`를 기록 → 머리글에 경고. 일부 종목만 실패하면 그 행만 오류로 표시.
- 새로 고침 1회 ≈ API 130~150회(관심·보유 18종목 기준, 종목당 약 4회). 종목을 늘리면 느려지므로 [설정] `종목별 수급 조회 = N`으로 줄일 수 있습니다.

사용 API (모두 `examples_llm/` 참고):

| 용도 | API | tr_id |

## 7. 문제 해결

| 증상 | 조치 |
|---|---|
| 머리글 “접근토큰 없음” / “유효한 접근토큰이 없습니다” | 모두 새로 고침 한 번 더 (첫 실행·재발급 직후) |
| `EGW00133` | 토큰은 1분당 1회 — 1분 후 다시 |
| `EGW00201`이 계속 | [설정] 종목별 수급 조회 = N, 관심종목 수 줄이기 |
| “이전 데이터(갱신 실패: …)” | 사유를 확인(설정 파일 경로·네트워크 등) 후 다시 새로 고침 |
| `Formula.Firewall` | [데이터] > [데이터 가져오기] > [쿼리 옵션] > 현재 통합 문서 > 개인 정보 수준 무시 |
| 종목명이 “⚠ 코드 확인” | 6자리 코드 확인. 종목DB에 없는 코드(ETF·ETN 등)는 대회 유니버스 밖일 수 있음 |

VBA로 자동화할 때는 `Application.CalculateUntilAsyncQueriesDone`을 쓰지 마세요. 쿼리가 통합문서 표를 읽는 동안 메인 스레드를 막아 멈출 수 있습니다(대화형 사용에는 해당 없음).

## 8. 보안·공유

- 앱키·시크릿은 통합문서에 저장되지 않습니다(Power Query가 `kis_devlp.yaml`을 직접 읽음).
- 숨김 시트 `_sys`의 `tblToken`에 24시간짜리 접근토큰이 캐시됩니다. 파일을 남에게 보내기 전에 이 표 내용을 지우세요.
- 대회 계좌 잔고는 자동으로 가져오지 않습니다. 대회 체결 내역을 [매매일지]에 옮겨 적는 방식이며, 대회가 한국투자증권 모의투자 계좌라면 잔고조회(VTTC8434R)·일별체결(VTTC0081R) 연동을 추가할 수 있습니다(모의투자 앱키 필요).
