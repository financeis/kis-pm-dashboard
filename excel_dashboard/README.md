# KIS PM Daily Dashboard (Excel + Power Query)

KOSPI·KOSDAQ 개별종목 모의투자대회(수익률·샤프지수 평가)를 운용역처럼 관리하기 위한 **일일 대시보드**입니다.
한국투자증권 Open API를 Excel Power Query가 직접 호출하며, 이 저장소 `examples_llm/`의 URL·tr_id·파라미터를 M 코드로 옮겼습니다.
**조회 전용**이며 주문·계좌 API는 쓰지 않습니다.

대회 종목 약 530개를 Q.Pack(삼성증권 퀀트 데이터팩) 'Company' 시트처럼 한눈에 보는 **[대회종목]**, KRX 업종·테마 시세의 **[업종]**,
한 종목을 깊게 보는 **[종목분석]**, 이벤트·뉴스의 **[뉴스·이벤트]** 페이지가 있고, 무거운 데이터는 페이지의 **버튼**으로 받습니다.

```
excel_dashboard/
├── KIS_PM_Dashboard.xlsm   # 생성된 통합문서(매크로 포함) — git 제외: 토큰 캐시·개인 매매기록
├── build_dashboard.py      # 통합문서 생성기(Excel COM) — 이관·백업·VBA 삽입 포함
├── migrate.py              # 기존 통합문서를 Excel로 열지 않고 읽어 이관 계획을 만듦
├── xl_helpers.py           # COM·서식·차트·Q.Pack 3색·열 묶음·버튼·VBA 삽입 헬퍼
├── xlsx_tables.py          # 통합문서의 표를 Excel 없이 파일에서 직접 읽기
├── powerquery/*.pq         # Power Query(M) 원본 — 통합문서 안의 쿼리와 동일
├── pages/*.py              # 새 페이지 빌더(대회종목·업종·종목분석·뉴스·이벤트)
├── vba/mod_refresh.bas     # 버튼 매크로([시세]·[전체]·[업종]·[조회]) — 빌더가 텍스트로 넣음
├── data/                   # 버전 관리 데이터: 대회 종목 명단·기본 테마표·NICS 코드표
├── tools/                  # 개발·검증 도구(쿼리 시험 하네스·명단 생성·검증 스크립트)
├── backup/                 # 빌드 전 자동 백업·빌드 로그 — git 제외
└── history/est_snap.csv    # Fwd EPS 스냅샷 이력 복사본([전체]마다) — git 제외
```

## 1. 준비

1. `~/KIS/config/kis_devlp.yaml`에 **실전투자** 앱키(`my_app`)·시크릿(`my_sec`)·도메인(`prod`)이 있어야 합니다(저장소 README 3.5절).
   시세·순위·수급 API는 모의투자 도메인에서 지원되지 않는 경우가 많아 실전 도메인으로 조회만 합니다.
2. Windows + Microsoft 365 Excel (LET·FILTER·SORTBY·TAKE·VSTACK·HSTACK·XLOOKUP·LAMBDA 사용).
3. **업종 분류 파일**: VALUESearch에서 내보낸 `수집기업_valuesearch.xlsx`(시트 `Sheet2`, 1행 머리글). 기본 위치는 저장소 루트이며,
   옮기면 [설정]의 `vs_path`만 바꾸면 됩니다. 이 파일은 git에 올리지 않습니다.
4. 통합문서를 다시 만들 때만 Python + `pywin32`, `pyyaml` 필요(개발·검증 도구는 `requests`도 사용).

## 2. 통합문서 만들기·다시 만들기

```powershell
python excel_dashboard/build_dashboard.py                      # 같은 폴더의 .xlsm(없으면 .xlsx)에서 자동 이관해 다시 만듦
python excel_dashboard/build_dashboard.py --migrate-from D:/old/KIS_PM_Dashboard.xlsx
python excel_dashboard/build_dashboard.py --no-migrate         # 이관 없이 새로(샘플 매매일지·관심종목)
python excel_dashboard/build_dashboard.py --no-migrate --empty # 빈 매매일지로 새로
python excel_dashboard/build_dashboard.py --cfg D:/my/kis_devlp.yaml   # 설정 파일 경로 지정(--visible: Excel 보이게)
```

- 걸리는 시간 약 7.5~8분. 별도의 숨김 Excel 인스턴스로 작업하고, 열려 있는 다른 Excel 창은 건드리지 않습니다.
- **빌드 전에 원본을 `backup/<이름>_YYYYMMDD_HHMMSS.<확장자>`로 복사**하고, 빌드 로그도 `backup/`에 남깁니다. 원본이 `.xlsx`였고 이관이 성공하면 그 `.xlsx`는 백업 폴더로 옮겨 집니다(살아 있는 통합문서는 `.xlsm` 하나).
- **이관되는 것**: 매매일지 전체, 관심종목, 설정(키별 — 쓰시던 값 유지, 새 키는 기본값 추가), 해외지수 목록, 휴장일, 수정표, 가격 이력·세션 달력·분기 실적·신용/공매도/대차·Fwd EPS 스냅샷(있으면), 유효한 접근토큰. 기존 통합문서는 **Excel로 열지 않고 파일을 직접 읽어** 옮깁니다(열면 토큰 확인이 돌아 새 토큰이 발급될 수 있음). 스냅샷이 통합문서에 없으면 `history/est_snap.csv`에서 복원합니다.
- 목록에 없는 사용자 추가 시트는 경고만 하고 옮기지 않습니다(백업본에 남음).
- 버튼 매크로를 넣는 동안만 Excel 보안 설정 'VBA 프로젝트 개체 모델에 대한 신뢰할 수 있는 액세스'(레지스트리 `AccessVBOM`)를 켰다가, 성공·실패와 관계없이 **원래 상태로 되돌립니다**(로그에 복원 결과 기록).
- 종료 코드: 0 성공 / 1 빌드 실패(원본은 그대로) / 2 토큰 남은 시간 부족(Excel을 띄우기 전에 멈춤 — 통합문서를 한 번 열어 토큰을 갱신한 뒤 다시) / 3 이관·설정 문제(Excel을 띄우기 전에 멈춤).

## 3. 처음 한 번

1. `KIS_PM_Dashboard.xlsm`을 열고 노란 보안 경고 줄이 뜨면 **[콘텐츠 사용]** (매크로와 데이터 연결 모두 필요). ‘웹 콘텐츠 액세스’ 창이 뜨면 **익명 → 연결**.
2. **[설정]**: 대회 시작일·종료일·초기자금·수수료율·거래세율·벤치마크를 대회 규정대로 확인.
3. **[데이터] > [모두 새로 고침]** (`Ctrl+Alt+F5`) — 약 1분 15초.
4. **[대회종목]**의 **[전체]** — 처음 한 번은 가격 이력 260세션 등을 모두 채우느라 **약 15분**(KIS 호출 약 5,900회). 이후 평일은 4~5분.

## 4. 버튼과 매일 루틴

| 버튼(시트) | 하는 일 | 실측 시간 |
|---|---|---|
| [모두 새로 고침] | 지수·시장 수급·업종 히트맵·해외지표·주도주 순위·시세판(외인·기관 추정가집계 포함)·보유/NAV/위험·뉴스·증시 자금. 버튼 전용 데이터는 건드리지 않음 | 약 72~84초(호출 130~150회) |
| [시세] (대회종목) | 마지막 세션 확인 → 페이지 종목 현재가(30종목/회) → 가격 이력의 마지막 세션 봉 갱신 → 기간 등락·지표·대회종목 표·테마 집계 재계산 | 30~37초(파일을 연 뒤 첫 실행 약 44초) |
| [전체] (대회종목) | [시세]의 모든 것 + 분류(VALUESearch) · 가격 이력 보정·첫 채우기 · 종목 수급 · 목표주가 · KIS 추정·스냅샷 · 이벤트 · 주간 항목 · KRX 업종 · 이력 CSV | 평일 약 4~5분(통합문서를 연 뒤 첫 실행은 준비·대기로 약 1.5~3분 추가), 처음 약 15분 |
| [업종] (업종) | KRX 업종지수·업종별 투자자 수급 + 테마 집계 | 18~20초 |
| [조회] (종목분석) | 종목코드 칸의 한 종목만 13개 구역을 한 번에 조회 | 약 1분(호출 약 33회) |

- 버튼 옆 **최근 조회**에는 끝난 시각, **상태**에는 `정상` / `일부 오류 n건` / `실패: <단계들> — 이전 데이터 표시 중`이 남습니다. 끝나면 단계별 요약 창이 뜹니다(실행 중 Esc로 멈춤).
- **주간 항목**(분기 실적, 신용·공매도·대차, 목표주가·KIS 추정 전체 재조사)은 마지막 성공 후 `weekly_days`(기본 7)일이 지났거나 [설정] `force_weekly = Y`일 때만 [전체]에서 돌고, 실행 뒤 `force_weekly`는 `N`으로 돌아갑니다. 그런 날의 [전체]는 10분 이상 걸릴 수 있습니다.
- 첫 [전체]를 누르기 전에는 [대회종목]의 지표가 빈칸입니다(정상).

| 시간 | 할 일 |
|---|---|
| 08:30 장 전 | [모두 새로 고침] → [시장] 해외지수·환율·금리·증시 자금 → [대시보드] 알림(손절·목표·비중) → 오늘 계획. 장 시작 전 [시세]는 새 봉을 만들지 않고 마지막 세션 봉만 갱신 |
| 장중 | 필요할 때 [모두 새로 고침](시세판·순위·추정가집계) + [시세] · [시장] 주도주(★)·수급 · [업종] 테마 흐름 · 관심 종목은 [종목분석] [조회] |
| 매매 직후 | [매매일지]에 한 줄(매매근거 필수) → [모두 새로 고침] |
| 15:40 이후 장 후 | **[전체]** (종목별 수급 API가 15:40 전에는 오늘 날짜를 받지 않음) → [성과] 샤프·MDD·초과수익 → [리스크] 위험기여 → [대회종목]·[업종]으로 내일 계획 |

## 6. 대회 종목·분류·수정표

- **대회 종목**: 2026-09-30 종가 × 상장주식수 **1,000억 이상** & KRX 거래대금 5거래일(09-22·23·28·29·30) 평균 **25억 이상**인 보통주(우선주·SPAC 제외, 외국기업 포함). 한 번 계산해 고정 — **527종목**(KOSPI 236·KOSDAQ 291), `data/contest_universe_20260930.csv`. 생성 스크립트 `tools/make_contest_universe.py`는 기준일·기준값을 인자로 받습니다.
- **NICS 분류**: VALUESearch 파일의 NICS 코드로 대분류 → 업종 → 세부 3단계. 업종까지만 분류된 종목은 세부 = 업종, 대분류까지만이면 업종 = 세부 = `대분류 (기타)`. 파일에 없거나 비면 KRX 지수업종으로 대체(분류출처 `KRX`). 대회 종목의 NICS 커버리지 98.3%.
- **테마**: 대회 종목마다 대테마 1개 + 세부테마 1개(대테마 20·세부테마 76, `data/themes_base.csv`, 근거 한 줄). Claude가 주요상품·KSIC·NICS·KIS 테마를 참고해 분류한 기본표입니다.
- **수정표**([설정] W8 `tblOverride`): 종목코드와 바꿀 칸만 씁니다(빈칸 = 수정 없음). `대회편입` = `추가`/`제외`, 대테마·세부테마·NICS 3단계는 기본 분류보다 항상 우선. 코드 형식·값이 틀리거나 종목DB에 없는 코드의 행은 무시되고 AB5에 `⚠ 수정표 n행 무시됨`이 뜹니다. 재생성 때도 그대로 이관됩니다.
- **섹터 기준**: [설정] `sector_basis` = 대분류 / 업종 / 세부(기본) / 대테마. 포트폴리오·리스크·대시보드·시세판·순위의 '섹터'가 따릅니다(값이 없으면 세부 → 업종 → 대분류 → KRX). 수정표나 섹터 기준을 바꾼 뒤에는 [모두 새로 고침]을 두 번 누르면 시세판·포트폴리오까지 반영됩니다.

## 7. 지표 정의

- **NAV(t)** = 초기자금 + 누적 현금흐름 + Σ 보유수량×종가(수정주가). **샤프** = (일간수익률 평균 − 무위험/252) ÷ 표준편차 × √252. **MDD**·**알파**(젠센, 연율)·**정보비율**. 평균단가는 매수 수수료 포함 원가 → 실현손익 + 평가손익 = 순자산 − 초기자금.
- **세션**: KOSPI 지수 일봉에 나타난 날짜(휴장일 목록에 의존하지 않음). 기간 등락은 세션 수 기준 — 1D=직전 세션, 1W=5, 1M=21, 3M=63, 6M=126, 1Y=250세션 전, YTD=직전 연도 마지막 세션. 60일 평균은 완료 세션(15:30 이후) 60개.
- **수급 %** = 외국인·기관계 순매수 1/5/21 완료 세션 합 ÷ 현재 시가총액.
- **후행 PER** = 현재가 ÷ TTM EPS(최근 4개 분기 단독 EPS 합), **PBR** = 현재가 ÷ 최근 분기 BPS. 분기 값은 회계연도 누적을 빼서 단독값으로 바꿉니다. **PER·PBR 변화(3M·6M·YTD·1Y)**는 그날 '알려진' 실적 기준 — 1~3분기는 분기말 + 45일, 4분기는 결산일 + 90일부터 반영(`fin_lag_q`·`fin_lag_y`로 조정). EPS·BPS ≤ 0이면 공란.
- **목표주가 컨센서스**: 증권사별로 최근 6개월(`target_window_months`) 안의 마지막 목표가(0·공란 제외) 평균. 괴리율 = 평균 ÷ 현재가 − 1, 1M·3M 변화.
- **Fwd EPS**(KIS 리서치 자체 추정, 컨센서스 아님) = FY1 EPS × r/12 + FY2 EPS × (12 − r)/12, r = FY1 결산월까지 남은 달 수(이번 달 포함). KIS 값의 EPS·비율은 ÷10 보정. **Fwd PER 변화(1W·1M)**: 기준 세션 이전 3세션 안의 스냅샷이 있으면 그 값, 없고 추정일이 기준일 이전이면 기준일 종가 ÷ 기준일 가중 Fwd EPS로 재구성, 둘 다 아니면 공란. 스냅샷은 [전체]마다 쌓입니다.
- **신용잔고율**(최신)·1M 변화(%p), **공매도 비중**(최근 5세션 평균 공매도 거래대금 ÷ 거래대금), **대차잔고 1M 변화율**.
- **테마 집계**: 대회 종목만, 현재 시가총액 가중 평균 등락, 상승 종목 비율, 테마 시가총액 대비 수급 %.
- 데이터가 없으면 0이 아니라 빈칸이고, 색 규칙도 빈칸은 칠하지 않습니다.

## 8. 데이터 흐름과 안정성

- **토큰**: `T_Token` 쿼리만 발급합니다(남은 유효시간 3시간 미만일 때만, 발급 시 알림톡 1건). 나머지 쿼리·버튼은 캐시만 읽습니다. 파일을 열 때와 30분마다 자동 확인.
- **버튼 전용 데이터**(가격 이력·지표·수급·실적·목표주가·추정·스냅샷·신용/공매도/대차·이벤트·KRX 업종·대회종목 표·테마 집계·종목분석 13개 표)는 [모두 새로 고침]·파일 열기·표 우클릭 새로 고침에서는 **KIS를 호출하지 않고** 저장된 값을 그대로 보여 줍니다. 버튼이 숨김 시트 `_seed`의 실행 제어 표 `tblRunCtl`에 모드를 적고 돌린 뒤 되돌립니다.
- 버튼 실행 직후 Excel이 쿼리를 한 번 더 평가하더라도 같은 버튼 실행 안에서는 다시 조회하지 않도록 막혀 있습니다. 통합문서를 연 뒤 첫 [전체]는 이 때문에 표를 한 번 미리 준비하고 잠시 기다립니다(합쳐서 약 1.5~3분).

## 9. 데이터 한계 (빈칸이 정상인 경우)

- KIS 추정실적은 이 종목군의 약 **21%**, 목표주가는 약 **58%**(3곳 이상 약 40%)만 있습니다. 추정은 한국투자증권 자체 추정이며 컨센서스가 아닙니다.
- 체결금액별 매매비중·당일 매물대·외인·기관 추정가집계는 **당일분만** 제공됩니다(추정가집계는 09:30·10:00·11:20·13:20·14:30 입력, 시세판에는 장중에만 표시).
- 종목별 투자자 수급의 오늘 값은 15:40 이후에 받을 수 있고 시간외 거래로 18시까지 조금 바뀔 수 있습니다. 신용잔고는 약 2영업일, 증시 자금은 1~2일 늦게 공표됩니다(표의 기준일 확인).
- 약 50종목은 KIS 재무 자료가 비었거나 오래돼 후행 PER이 빈칸이거나 최근 분기가 늦습니다([대회종목] 최근분기 열로 확인).
- 상장정보 일정은 약 3영업일 앞까지만 나와 CB·BW 전환 상장·신규상장은 며칠 전에야 보입니다. 12~3월에는 연말 정기주총 일정이 매우 많아 `오류: 주주총회 … 일부 누락 가능`(일부 오류 1건)이 뜰 수 있습니다.
- 주식형 펀드 잔고는 평가액이라 주가 등락을 따라 움직입니다.
- 장 시작 직후(대략 09:00~10:00) KIS의 오늘 KOSPI 일봉이 아직 없으면 [시세]가 `오류: 오늘 세션 미확인`을 표시합니다. 10시 개장일·수능일 같은 특수 개장 시간은 반영하지 않습니다.
