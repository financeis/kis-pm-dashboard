# 0001. Power Query가 KIS를 직접 호출하고 무거운 데이터는 버튼으로

## 배경
대시보드는 Excel에서 매일 쓰는 도구이고 사용자는 Excel + Power Query를 원했다. 대회 종목 약 530개의 가격 이력·수급·실적·목표가·추정을 매번 모두 받으면 [모두 새로 고침] 한 번에 6~8분, KIS 호출 수천 회가 들어 장중에 쓸 수 없다.

## 결정
모든 데이터 수집은 Power Query가 KIS REST를 직접 호출한다. 가벼운 데이터(지수·시장 수급·순위·보유 종목 시세·뉴스·증시 자금)만 [모두 새로 고침]에 두고, 무거운 데이터는 페이지 버튼([시세]·[전체]·[업종]·[조회])이 VBA로 정해진 표만 순서대로 새로 고친다. 버튼 전용 쿼리는 실행 모드 표를 보고 버튼이 아닐 때는 KIS를 부르지 않는다.

## 대안
- 파이썬 수집기 + CSV: 매일 별도 프로그램을 돌려야 하고 Excel만으로 끝나지 않는다 — 사용자가 채택하지 않았다.
- 전부 [모두 새로 고침]: 장중 대기 시간이 길고 호출 한도에 자주 걸린다.
- 매 실행 전체 조회: 6~8분 — 변경분 방식으로 [시세] 30초대, [전체] 4~5분.

## 결과
- `.xlsm`이 필요해졌고 사용자는 파일을 열 때 매크로를 허용해야 한다. 빌드는 VBA 삽입을 위해 AccessVBOM을 잠시 켰다 되돌린다.
- 버튼 쿼리는 build 모드에서 호출이 없어야 하므로 빌드는 무거운 데이터를 채우지 않고, 첫 [전체]가 약 15분 걸린다.
- 계산 쿼리는 적재된 표를 읽으므로 버튼의 새로 고침 순서가 정확성의 일부가 됐다. 순서를 바꾸면 한 박자 늦은 값이 나온다.
