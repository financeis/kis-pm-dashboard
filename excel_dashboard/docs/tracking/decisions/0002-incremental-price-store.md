# 0002. 가격 이력은 변경분만 이어 붙이고 세션은 KOSPI 일봉으로

## 배경
기간 등락(1D~1Y)·20일 줄무늬·60일 평균에 종목마다 260세션 일봉이 필요하다. 일봉 API는 100행/회라 530종목 전체를 매번 받으면 약 1,600회다. 멀티 시세 API(30종목/회)는 싸지만 응답에 날짜가 없어, 장 시작 전·휴장일에 그 값을 '오늘 봉'으로 저장하면 가짜 세션이 영구 이력에 끼거나 어제 확정 봉을 덮어쓴다.

## 결정
가격 이력은 자기 표를 다시 읽어 이어 쓰는 저장소로 둔다. [시세]는 멀티 시세로 **마지막 세션 봉**만 추가·갱신하고, [전체]가 빠진 세션 보충·수정주가 변동 재조회·첫 260세션 채우기를 한다. 세션 날짜는 KOSPI 지수(0001) 일봉 날짜로 정하고, 개장일 09:00 이후인데 달력에 오늘이 없으면 저장소를 건드리지 않고 오류 1건을 남긴다.

## 대안
- 매번 전체 일봉: [시세]만 4~5분.
- 수작업 휴장일 목록으로 날짜 결정: 목록이 불완전하면 가짜 세션이 생긴다.
- 멀티 시세 값을 무조건 오늘 날짜로: 장 시작 전·휴장일에 어제 봉을 덮어쓴다.

## 결과
- 수정주가 변동은 시세를 받은 세션에서만 감지되므로 권리락일에 [전체]를 건너뛰면 그 앞 이력이 수정 전 값으로 남는다(매일 [전체] 권장).
- 장 시작 직후 KOSPI 일봉에 오늘이 생기기 전에는 [시세]가 갱신을 하지 않는다.
- 저장소가 13만 행이 되어 [시세]가 30초대로 목표(10~30초)를 넘는다.
- 재생성 때 저장소는 시드 표로 이관해야 한다(Power Query 표에는 행을 직접 쓸 수 없음).
