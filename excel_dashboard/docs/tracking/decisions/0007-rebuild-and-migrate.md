# 0007. 재생성 + 파일 파싱 이관 + 시드 표

## 배경
통합문서는 파이썬 빌더가 쿼리 원본·레이아웃 코드로 매번 새로 만든다. 그런데 매매일지·관심종목·설정·수정표·스냅샷·가격 이력 같은 사용자 데이터와 이력은 잃으면 안 된다. 기존 통합문서를 Excel로 열면 파일 열 때 새로 고침으로 `T_Token`이 돌아 토큰이 새로 발급될 수 있다(알림톡). Power Query가 채우는 표에는 빌더가 행을 직접 써 넣을 수 없다.

## 결정
빌더는 이관 원본을 먼저 백업하고 `migrate.py`로 파일(zip/XML)을 직접 파싱해 읽는다. 입력표는 새 통합문서에 직접 쓰고, Power Query 저장소 표의 행은 같은 열의 정적 `…Seed` 표에 넣어 자기참조 쿼리가 첫 실행 때 읽게 한다(복사 뒤 시드는 비움). 토큰도 파싱해 새 통합문서 토큰 표에 심어 재사용시킨다.

## 대안
- 통합문서를 직접 고치는 업데이트 스크립트: 쿼리·서식·버튼의 일관성을 유지하기 어렵다.
- 기존 통합문서를 Excel로 열어 복사: 토큰 발급 위험.
- 토큰을 JSON 파일로 넘기기(`--seed-token`): 토큰이 통합문서 밖 파일에 남는다 — 옵션은 남겼지만 쓰지 않는다.

## 결과
- 빌드가 약 8분 걸리고, 원본을 읽을 수 없으면 새로 만들지 않고 멈춘다(`--no-migrate`일 때만 새로).
- 이관 대상에 새 표를 추가할 때는 `migrate.py`와 시드 표, 자기참조 쿼리의 시드 읽기를 함께 바꿔야 한다.
- 원본 `.xlsx`는 성공 뒤 백업 폴더로 옮겨져 살아 있는 통합문서는 `.xlsm` 하나다.
