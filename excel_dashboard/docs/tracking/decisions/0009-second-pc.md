# 0009. 다른 PC에서는 통합문서를 직접 옮기고, 경로는 매크로가 맞춘다

## 배경
노트북에서 만든 대시보드를 메인 컴퓨터에서도 써야 한다. 통합문서에는 접근토큰과 매매기록이 들어 있어 git에 올릴 수 없고, [설정]의 KIS 설정 파일 경로(`cfg_path`)와 VALUESearch 경로(`vs_path`)는 노트북의 절대 경로(사용자 폴더 이름 포함)로 저장돼 다른 PC에서는 맞지 않을 수 있다.

## 결정
코드는 개인 비공개 GitHub 저장소(`financeis/kis-pm-dashboard`, 원격 `origin`)에 올리고, 통합문서·`history\`·VALUESearch 파일·`kis_devlp.yaml`은 사용자가 직접 옮긴다. 매크로 `FixLocalPaths`가 사용자가 통합문서를 열 때(`Auto_Open`)와 모든 버튼 시작에서, 지금 경로에 파일이 없고 표준 위치(`%USERPROFILE%\KIS\config\kis_devlp.yaml`, 통합문서 폴더·상위 폴더의 `수집기업_valuesearch.xlsx`)에 파일이 있을 때만 두 경로를 바꾼다. 다른 PC에서 다시 빌드할 때도 빌더가 같은 규칙으로 기본 위치를 쓴다.

## 대안
- 통합문서를 git에 올리기: 토큰·매매기록이 원격에 남는다(비공개라도 금지 규칙).
- 쿼리에서 경로 맞추기: Power Query M은 환경 변수를 읽지 못한다.
- 사용자가 [설정]을 직접 고치기: 사용자 폴더 이름이 다른 두 PC에서 하나의 통합문서(동기화 폴더)를 번갈아 쓰면 바꿀 때마다 고쳐야 한다.
- 공식 저장소를 GitHub에서 포크: 공개 저장소의 포크는 공개라 개인 작업이 드러난다.

## 결과
- 처음 열 때 [콘텐츠 사용]을 눌러야 경로가 맞춰진다(모든 버튼도 시작할 때 다시 확인). 매크로가 막혀 있으면 경로도 버튼도 동작하지 않고, 경로가 맞춰지기 전에 파일을 열 때 돈 토큰 확인은 한 번 실패할 수 있다.
- 두 PC에서 번갈아 쓰려면 통합문서 하나만 원본으로 둬야 한다(동시에 열지 않기). 동기화 폴더는 일반 폴더 경로로 보이는 것(Google Drive·Dropbox)이어야 한다 — OneDrive에서 연 통합문서는 `ThisWorkbook.Path`가 인터넷 주소로 나올 수 있어 이력 CSV 저장과 경로 맞추기가 실패할 수 있다.
- 저장소 루트 `kis_devlp.yaml`의 이 PC 작업 사본에는 실제 앱키가 있어 `skip-worktree`로 커밋에서 빠지게 했다.
