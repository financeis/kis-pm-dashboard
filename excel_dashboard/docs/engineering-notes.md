# 엔지니어링 노트

## Excel·Power Query 함정

- **새로 고침 직후 다시 도는 쿼리** — 증상: build 모드 새로 고침만 했는데 KIS 요청이 나가고, 버튼 한 번에 같은 요청이 두 번 나간다(요청을 세는 모의 서버로 확인). 원인: Excel은 새로 고침이 끝난 직후 쿼리를 백그라운드에서 한 번 더 평가하며 최상위 단계도 따로 평가한다. Power Query 백그라운드 캐시에 없는 요청(동기 새로 고침으로 받은 것, 날짜가 바뀐 요청)은 서버로 다시 나간다. 대응: 조회를 함수 단계에 두고 활성 모드에서만 호출, `tblRunCtl.started` ≤ 자기 표 최신 조회시각이면 자기 표 반환. 확인: build 새로 고침 뒤 10초 동안 요청 0, 같은 `started`로 두 번째 새로 고침 요청 0.
- **통합문서를 연 뒤 첫 활성 새로 고침의 중복** — 증상: 파일을 열고 처음 누른 [전체]에서 실적·신용 표 요청이 두 배. 원인: 표가 쓰이기 전에 Excel이 병렬 평가를 시작해 `started` 가드가 아직 통과된다. 대응: [전체]는 이번 Excel 세션에서 아직 새로 고치지 않은 자기 표를 build 모드로 먼저 한 번 새로 고친다(표별 추적, `RefreshedTables()`로 확인). [시세]·[업종]은 준비 비용(+25초·+10초)이 막는 중복(약 20·47회)보다 커서 준비하지 않는다.
- **표 첫 적재 직후 새로 고침의 2배 요청** — 새로 적재한 쿼리 표의 첫 새로 고침은 요청이 두 번 나간다(아무 쿼리나 동일). 빌더가 버튼 표를 build 모드로 처음 적재하는 이유다. 시험에서 build 새로 고침 직후 몇 초 안에 full로 바꿔 새로 고치면 `T_Est` 요청이 두 배가 됐다 → 시험은 build와 활성 새로 고침 사이에 12초 이상 둔다.
- **`started`가 초 단위라 한 박자 늦은 계산** — 증상: 세션 첫 [시세] 뒤 테마 집계가 실행 전 가격으로 남음. 원인: 준비 새로 고침과 `started`가 같은 초여서 가드가 '이미 계산함'으로 판단. 대응: 매크로가 다음 초까지 기다린 뒤 `started`를 쓴다.
- **조건부 서식이 깨지는 PQ 표** — 증상: 0~1행 표가 N행으로 늘면 서식 범위가 흩어지고, 규칙이 100개를 넘으면 새로 고침 중 Excel이 죽는다. 0행 새로 고침이 셀을 지워 아래 표가 끌어올려지고 다음 새로 고침이 실패한다. 원인: 기본 `RefreshStyle`(셀 삽입/삭제). 대응: 적재 직후·첫 새로 고침 전에 `RefreshStyle = 0`, 서식은 예약한 고정 범위(예: 대회종목 1,200행)에 걸고 규칙 수를 50개 안팎으로. 확인: 0 → 19 → 528 → 19행으로 새로 고쳐 규칙 수·적용 범위 불변.
- **`fnFallback` 결과의 날짜가 숫자로 보임** — 원인: 직전 표를 다시 읽은 결과에 열 형식이 없어 Excel이 G/표준으로 적재. 대응: `Table.TransformColumnTypes`로 형식을 다시 입힌다. 확인: 설정 경로를 일부러 틀리게 해 대체 경로를 탄 뒤 날짜 칸 서식.
- **오류가 빈 행이 되는 버퍼** — `List.Buffer`·`Table.Buffer`는 항목 안의 오류를 올리지 않고 빈 행으로 적재한다. 종목별 `try` 안에서 모든 값을 강제 평가해야 '그 종목만 오류' 처리와 '모두 실패 → 직전 표 유지'가 동작한다.
- **적재된 표를 읽는 쿼리는 한 박자 늦다** — 새로 고침 중 다른 쿼리의 결과를 직접 공유하지 않으므로 계산 쿼리는 적재된 표를 읽고, 그래서 버튼 순서(원천 → 지표 → 대회종목 표 → 테마 집계)가 곧 정확성이다. 수정표나 `sector_basis`를 바꾼 뒤 시세판·포트폴리오가 새 섹터를 보려면 [모두 새로 고침]을 두 번 해야 하는 것도 같은 이유다.
- **백그라운드 새로 고침 완료가 늦게 감지됨** — Excel은 백그라운드 완료를 타이머로 확인하고 간격이 1 → 5 → 20초로 늘어난다(상수 쿼리도 20초). 하네스는 자기 Excel 창에만 `WM_TIMER`를 보내 0.2초로 줄인다. 다른 프로세스의 창에는 보내지 않는다.
- **`CalculateUntilAsyncQueriesDone` 교착** — 통합문서 표를 읽는 쿼리가 있으면 이 호출이 메인 스레드를 막아 멈춘다. 자동화는 `QueryTable.Refreshing`을 폴링한다.
- **열 묶음 병합** — 같은 수준의 열 묶음이 나란히 있으면 하나로 합쳐진다. 접는 묶음마다 왼쪽에 보이는 비그룹 열이 있어야 한다(대회종목은 각 묶음의 첫 열을 보이게 둠). 활성 셀이 표 안이면 요약 열 위치 설정을 Excel이 거부하므로 셀 선택을 표 밖으로 옮긴 뒤 설정한다. 이 시트에서는 `ClearOutline`도 거부돼 열마다 `Ungroup`한다.
- **조건부 서식 우선순위** — COM으로 추가한 규칙은 가장 낮은 우선순위로 들어간다. Q.Pack 규칙은 `SetFirstPriority`로 올려야 보유 행 배경색 아래에 가려지지 않는다.
- **Q.Pack 기준점이 0이 되는 표** — 행이 1개(빈 PQ 표도 1행으로 계산)이고 그 행이 조건을 만족하지 않으면 `qpack_anchor_formula`의 COUNT가 FALSE를 세어 기준점이 0이 된다. 대응: `tbl[[#All],[열]]`처럼 머리글을 포함한 범위를 주거나 SUMPRODUCT 가드로 감싸 빈칸이 되게 한다(대회종목·업종 페이지가 그렇게 함).
- **표 열의 차트** — 0행 표에는 표 열에 묶인 계열을 만들 수 없고, 1행일 때 만든 계열은 표가 커져도 따라가지 않는다. 종목분석 차트는 데이터 행 수를 세는 숨은 이름(`분석차트_*`)을 계열로 쓴다.
- **숫자 셀의 IndentLevel·좁은 칸** — PDF/PNG 렌더에서 IndentLevel을 준 숫자 칸과 [시장] 지수 카드 같은 16pt 숫자가 `####`로 보인다. 화면(85%·100%)에서는 정상이라 레이아웃은 바꾸지 않았다. 들여쓰기가 필요한 숫자 열은 `_)` 같은 서식으로 처리한다.
- **VBA 소스 코드 페이지** — `CodeModule.AddFromString`은 cp949로 저장해 `—`·`✓`·`⚠`를 `?`로 바꾸고, MsgBox도 cp949를 거쳐 `—`를 깬다(창에는 U+2015로 대신 표시, 셀에는 진짜 U+2014). `.bas` 가져오기(Import)는 파일을 CP949로 읽어 한글이 깨지므로 쓰지 않는다. 새 모듈에 VBE가 자동으로 넣는 `Option Explicit` 줄은 삽입 전에 지운다.
- **AccessVBOM 읽는 시점** — Excel은 이 값을 인스턴스 시작 때 한 번 읽는다. 켜기 전에 띄운 인스턴스는 켠 뒤에도 VBA 프로젝트에 접근하지 못하고, 켠 동안 띄운 인스턴스는 복원 뒤에도 접근한다. Excel은 종료할 때 값을 되쓰지 않는다.
- **`Application.StatusBar`** — 초기화 뒤 읽으면 화면은 '준비'인데 문자열 "FALSE"가 돌아온다. 자동화 검사는 `StatusBar is False`로 판정하지 않는다.
- **PQ 표의 `SourceType`** — 저장·다시 열기 뒤 Power Query 표는 `ListObject.SourceType = 3`으로 보고된다(0이 아님).
- **`_data` 시트에 표 추가** — `_data!EL2`에 증시 자금 표를 두면 `tblPositions` 계산열 추가가 오른쪽 셀을 밀어 빌드가 실패했다. 버튼·새 표는 `_calc`에 45열 간격으로 둔다.
- **[설정] 표 아래 공간** — 기존 입력표(관심종목·설정)와 같은 열에 표를 두면 그 표들의 행 삽입·삭제를 Excel이 거부한다("셀이 이동될 수 있기 때문에"). 수정표를 W8에 둔 이유다. 설정 키가 29개를 넘으면 표 아래 안내 문구가 표에 빨려 들어간 적이 있어, 안내는 설정표 끝에서 띄운 행에 둔다.

## KIS API 동작 (실측)

- **종목별 투자자 일별**(FHPTJ04160001): 오늘 날짜는 15:40 전까지 거부(`OPSQ2001 TIME LIMIT`). 없는 종목코드는 오류 대신 가격·수급이 빈 30행을 준다 → 가격이 있는 행만 세션으로 친다. 상장일 행은 거래량이 있어도 수급이 0이고 상장 전 날짜는 0으로 채워진다. 금액 백만원.
- **멀티 시세**(FHKST11300006): 30종목/회, 영문 포함 코드 동작. `inter2_sdpr` = 기준가(분할 반영 전일 종가 — 오늘 등락·상하한가의 기준), `inter2_prdy_clpr` = 원 전일 종가(예: 액면병합 재상장 종목에서 3,015 대 603). 정지 종목은 OHLC·거래량 0에 직전 종가.
- **KOSPI 일봉의 오늘 행**: 10:50·11:37에는 이미 있었다. 처음 생기는 시각은 측정하지 못했다 — 다음 개장일 09:00~09:30에 `inquire-investor-daily-by-market`(FHPTJ04040000, 0001)을 1분 간격으로 조회해 확인한다.
- **시장별 투자자 일별**(FHPTJ04040000)은 KRX 업종코드도 받아 업종당 약 300세션의 지수 종가와 투자자 수급을 한 번에 준다(`FID_INPUT_ISCD`=`FID_INPUT_ISCD_2`=업종코드, `FID_INPUT_ISCD_1`=KSP/KSQ). 없는 업종코드에는 다른 지수 값에 수급 0을 돌려주므로 업종 목록은 `idxcode.mst.zip`에서 만든다. KRX 테마형 지수(4xxx)는 0.
- **업종 구분별 전체시세**(FHPUP02140000, 기존 [시장] 히트맵): KOSDAQ 목록이 100행에서 잘리고 호출마다 내용이 달라 제조·건설·통신·IT 서비스 업종이 무작위로 빠진다.
- **종목투자의견**(FHKST663300C0): 최대 100행, 최신순. 잘려도 `tr_cont`가 비어 있고 `tr_cont=N`은 같은 페이지를 다시 준다 → 가득 찬 페이지의 가장 오래된 날짜까지로 기간을 줄여 다시 요청한다. 증권사명 `mbcr_name`(저장소 샘플의 열 매핑에 없음).
- **종목추정실적**(HHKST668300C0): 연도는 `output4.dt` 라벨(예: 2023.12 … 2027.12E, 오래된 종목은 2025.12E에서 끝남)로 맞춘다. EPS와 비율·배수는 ÷10, 금액은 억원. 첫 N/A 행에서 행이 잘린다(적자 연도 → 비율 표 3행, 은행 → 비어 있음). 커버하지 않는 종목도 `rt_cd 0`에 빈 배열. PER은 추정일 가격 기준이라 현재가로 다시 계산한다. 저장소 샘플의 열 매핑은 틀렸다.
- **재무**(손익계산서 FHKST66430200, 재무비율 FHKST66430300): 분기 값은 회계연도 누적. 약 50종목은 분기 값이 모두 0이거나 연간만 있거나 몇 분기 늦다.
- **예탁원 정보**: 상장정보는 연속 조회 커서가 넘어가지 않는 경우가 있어 날짜·코드 커서(`CTS`)와 요청 헤더 `tr_cont=N`을 함께 보내야 다음 페이지가 온다(헤더만이면 같은 페이지, 커서만이면 무시). 주주총회는 안건마다 1행·페이지당 20행이고 영문 포함 코드를 커서로 주면 처음부터 다시 시작해 숫자 코드로 보낸다. 상장정보 일정은 약 3영업일 앞까지만 있다. 12/31 기준일 정기주총은 수천 행이라 그 날짜를 건너뛰고 '일부 누락 가능' 오류 1건을 남긴다.
- **공매도 일별**: 오늘 행이 공표 전까지 0으로 와 평균을 끌어내리므로 오늘은 뺀다. 신용잔고는 T+2 공표, 신용잔고율은 소수 둘째 자리 %이고 분모가 상장주식수와 다를 수 있다. 대차는 잔고 주수(`rmnd_stcn`)를 쓴다(금액은 가격 평가라 제외).
- **뉴스 제목**: 없는 코드도 성공에 빈 목록. 시장 공통 자동 기사(예: 인포스탁 상위 20 목록)가 종목마다 붙어 같은 제목이 반복되고, 대형주는 시간당 약 40건이라 전체 100건이 1~2시간 분량으로 찬다. 관련 종목 칸(`iscd1~10`)은 조회한 종목과 다를 수 있어 종목명은 코드와 이름이 짝지어진 행에서 한 번만 가져온다.
- **증시 자금**(FHKST649100C0): 이미 억원(예탁금 × 회전율 ÷ 거래대금으로 교차 확인). 날짜 인자는 '이날까지'. 하루 이틀 늦게 공표.
- **외인·기관 추정가집계**(HHPTJ04160200): 입력 코드 1~5 = 09:30·10:00·11:20·13:20·14:30, 각 시점 몇 분 뒤에 나타남(13:20분은 13:27 전, 14:30분은 14:36 전). 기관은 10:00부터. 수량 누적이라 금액은 현재가를 곱한 근사.
- **당일 매물대**(FHPST01130000): 가격대 최대 100개에서 잘려 비중 합이 1보다 조금 작을 수 있다.

## 반복 작업 체크리스트

- **버튼 쿼리 추가·수정**: ① 조회는 함수 단계, 활성 모드에서만 호출 ② `started` 가드 ③ 자기 표 → Seed → 빈 표 순서의 비활성 경로 ④ 형식을 다시 입힌 대체 경로 ⑤ 종목별 강제 평가 ⑥ `상태`·`조회시각` ⑦ 하네스로 활성·build 모드 실행 — build에서 요청 0을 모의 서버나 끊어진 설정 경로(`cfg_path`를 없는 파일로)로 확인 ⑧ 원천 응답으로 파이썬 재계산 ⑨ 빌더 `LOADS`·버튼 순서·VBA 단계 목록·'모두 새로 고침 제외'에 등록.
- **페이지 추가·수정**: 모듈은 `SHEET`·`LOADS`·`prepare_tables`·`build` 제공, 표 아래 최대 행 수만큼 비워 둠, 0 → N행 새로 고침으로 서식·차트 확인, 하네스의 대역 빌더로 PNG 렌더, 빌더 등록 후 복사본 빌드로 다시 확인.
- **안전한 빌드**: 원천 토큰 남은 시간(`python excel_dashboard/tools/kis_dev.py`) 210분 이상 → 먼저 복사본(`--migrate-from <복사본> --out <스크래치>\x.xlsm`)으로 → 로그의 행 수 대조·AccessVBOM 복원 줄 확인 → 실제 빌드. 사용자가 그 통합문서를 Excel로 열어 두었으면 빌드하지 않는다(파일 잠금).
- **하네스 시험**: `Harness(sample=True)`, 작은 명단 CSV(≤30종목)로 `h.static("tblContest", …)`, 활성 모드는 `h.runctl(mode=…, started="now")`. 토큰이 필요 없는 페이지 시험은 `use_token=False`. 결과 통합문서는 저장소 밖에만 저장된다.
- **수정주가 변동 모사**: 하네스에서 `set_cells("tblPxStore", {"종목코드": …, "일자": …}, {"종가": 1})` 뒤 full 실행 → 그 종목만 다시 받는지.
- **장 시작 전 모사**: 복사본에서 `tblRunCtl.now_override`를 다음 개장일 08:30으로 → [시세] → 새 봉이 없는지 → `now_override` 비우기.
