# 보안 정책

## 보호 대상

| 자산 | 위치 | 노출되면 |
|---|---|---|
| 앱키·시크릿(실전), 계좌번호, HTS ID | `~/KIS/config/kis_devlp.yaml`만 | 계좌 명의로 API 호출 가능 — 가장 중대 |
| 접근토큰(24시간) | 통합문서 숨김 시트 `_sys`의 `tblToken`, 그리고 그 통합문서의 백업본(`backup/*.xlsm`·`*.xlsx`) | 만료 전까지 시세·정보 조회를 대신할 수 있음 |
| 매매일지·관심종목·설정 | 통합문서, 백업본 | 개인 운용 기록 노출 |
| 사용자 제공 자료 | 저장소 루트 `수집기업_valuesearch.xlsx`, Q.Pack PDF | 유료 데이터·보고서 유출 |

## 인증 흐름 (KIS 접근토큰)

1. 쿼리가 KIS를 부를 때마다 `fnCfg`가 [설정] `cfg_path`의 yaml에서 앱키·시크릿·도메인을 읽는다. 파일이 없거나 `my_app`·`my_sec`·`prod` 중 하나라도 비면 즉시 오류(재시도 없음) → 그 표는 직전 데이터 유지·`이전 데이터(갱신 실패: …)`.
2. `fnToken`은 `tblToken`에서 `env = prod`이고 만료까지 5분 넘게 남은 토큰만 돌려준다. 없으면 오류 "유효한 접근토큰이 없습니다" → 사용자는 [모두 새로 고침]을 한 번 더.
3. **토큰 발급은 `T_Token` 쿼리만** 한다. 남은 유효시간 ≥ 3시간이고 앱키가 같으면(앱키 체크섬 비교) 재사용, 아니면 `oauth2/tokenP`로 1회 발급. 발급할 때마다 사용자에게 카카오톡 알림이 가고 1분에 1회만 허용된다(`EGW00133`). 발급이 실패하면 기존 토큰이 아직 유효할 때 그대로 쓰고, 없으면 토큰 칸을 비운 채 상태에 사유를 남긴다.
4. `T_Token`은 파일을 열 때와 30분마다 자동으로 돌고, 모든 버튼의 첫 단계다. 다른 쿼리·도구는 토큰을 발급하지 않는다.
- 금지: 여러 쿼리·통합문서가 각자 발급하는 구조(알림 폭주·1분 제한), 토큰을 JSON·CSV·로그 등 통합문서 토큰 표 밖에 저장하는 것.

## 비밀값 취급

- 앱키·시크릿·토큰·계좌번호·HTS ID는 어떤 출력·로그·커밋에도 쓰지 않는다. 확인은 길이·형식·남은 시간(분)으로만 한다.
- 앱키·시크릿은 통합문서에 저장하지 않는다(쿼리 정의·연결 문자열·VBA 포함). 빌드 결과물 검사(`tools/verify_security.py`)가 통합문서 모든 파트, 쿼리 원본, VBA, 이력 CSV, 빌드 로그를 검색해 확인한다.
- 토큰은 `_sys`에만 있어야 한다. 다른 시트·쿼리·연결에 토큰 문자열이 있으면 결함이다.
- 통합문서·`backup/`·`history/`·사용자 제공 자료는 git에서 제외한다. 통합문서를 남에게 보낼 때는 `tblToken` 내용을 지운다.

## 개발 중 토큰 규칙

- 토큰 원천은 통합문서 하나(지금은 `excel_dashboard/KIS_PM_Dashboard.xlsm`)다. 도구는 원천을 **Excel로 열지 않고 파일을 직접 파싱**해 토큰을 읽어 메모리에서만 쓴다 — 열면 '파일 열 때 새로 고침'으로 `T_Token`이 돌아 발급될 수 있다.
- 시험용 통합문서에는 `T_Token`을 넣지 않고 정적 `tblToken`에 복사한다. 원천의 남은 유효시간이 210분(3시간 30분) 미만이면 도구·빌더는 호출 없이 멈춘다(빌더 종료 코드 2). 이 기준이 `T_Token` 재발급 기준(3시간)보다 길어 빌드 결과물도 발급 없이 재사용만 한다.
- 버튼 실행 검증만 원천을 Excel로 연다: 한 번에 하나씩, 열기·버튼 실행 직전마다 남은 시간을 다시 확인하고, 실행 뒤 저장한다(그 안에서 토큰이 갱신됐다면 잃지 않게).
- 갱신은 한 사람이 한 번에: 원천을 `backup/`에 복사 → 별도 Excel로 열어 파일 열 때 새로 고침이 끝나길 기다림 → 남은 시간이 3시간 이상이면 `tblToken`의 `expires`를 현재 시각으로 바꿈 → `T_Token`만 동기 새로 고침(1회 발급) → `status`가 `신규 발급`이고 만료가 20시간 넘게 남았는지만 확인해 저장, 아니면 저장하지 않고 닫은 뒤 1분 뒤 다시 하거나 백업을 되돌림.

## VBA 신뢰 설정

- 빌더는 VBA 텍스트를 넣는 동안만 `HKCU\Software\Microsoft\Office\16.0\Excel\Security\AccessVBOM`을 1로 켜고, 성공·실패와 관계없이 **원래 상태**(값 / 값 없음 / 키 없음)로 되돌린 뒤 다시 읽어 확인한다. 복원 결과는 빌드 로그에 한 줄로 남는다. 복원이나 확인이 실패하면 빌드는 오류로 끝나며 사용자가 직접 되돌려야 할 상태를 메시지에 적는다.
- 사용자는 통합문서를 열 때 [콘텐츠 사용]으로 매크로·데이터 연결을 허용한다. 매크로가 막히면 버튼만 동작하지 않고 [모두 새로 고침]은 된다.

## 기록 (감사 대상)

- 빌드 로그(`backup/<이름>_<시각>_build.log`): 이관 원본·백업 경로, 표별 이관 행 수(원본 → 새), 토큰 이관 여부와 남은 분, AccessVBOM 복원 결과, 경고(알 수 없는 시트 등).
- 버튼: `tblRunCtl`의 `last_summary`(단계별 판정·사유·소요 시간)와 각 페이지의 최근 조회 시각·상태 칸.
- 표: 모든 Power Query 표의 `상태`·`조회시각` 열(토큰 표는 `status`·`checked`).
