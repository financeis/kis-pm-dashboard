# Excel PM 대시보드 구축 작업 기록 (2026-09-30 세션)

KOSPI·KOSDAQ 개별종목 모의투자대회(수익률·샤프지수 평가)용 **일일 운용 대시보드**를 Excel + Power Query로 만든 세션의 전체 기록입니다.
무엇을 했는지, 어떤 오류가 났고 어떻게 해결했는지, 무엇을 검증했는지, 남은 주의사항을 정리했습니다.

- 결과물 위치: `excel_dashboard/` (사용법은 [`excel_dashboard/README.md`](../excel_dashboard/README.md))
- 작업 시간: 2026-09-30 20:28 ~ 23:40경 (22:38경 세션 중단 → 22:49 재개)
- 데이터 소스: 한국투자증권 Open API (이 저장소 `examples_llm/` 샘플의 URL·tr_id·파라미터), KIS 종목정보 마스터 파일(`stocks_info/`와 동일)

## 1. 요구사항과 결정 사항

| 요구 | 반영 |
|---|---|
| 2개월 대회, KOSPI+KOSDAQ 개별종목 유니버스 | 종목 마스터에서 ETF·ETN·리츠·펀드 제외, SPAC·거래정지·정리매매는 `대회편입=N`, 매매일지에 유니버스 외 코드 경고 |
| 수익률·샤프 등으로 평가 | 매매일지 + 수정주가로 일별 NAV를 재구성해 샤프(rf 적용/rf=0)·MDD·알파·정보비율 등 27개 지표 계산 |
| 실제 운용역 같은 일일 대시보드, 대회 후에도 사용 | 대시보드·시장·포트폴리오·리스크·성과·시세판·매매일지·매매분석·종목DB·설정·가이드 11개 시트 |
| 데이터 소스는 저장소 샘플 참고 | `examples_llm/`의 API 사양을 그대로 M 함수로 옮김 (조회 전용) |
| 플랫폼은 Excel Power Query | 모든 데이터 수집을 Power Query가 직접 수행, 분석·표시는 Excel 수식(동적 배열) |

### 주요 설계 결정

1. **Power Query가 API를 직접 호출** (Python 수집기 + CSV 방식은 쓰지 않음) — 요구사항 그대로, [모두 새로 고침] 한 번으로 끝나게.
2. **앱키·시크릿을 통합문서에 저장하지 않음** — PQ가 `~/KIS/config/kis_devlp.yaml`(저장소 샘플이 쓰는 그 파일)을 직접 읽음.
3. **실전 도메인으로 조회만** — 사용자의 설정 파일에 모의투자 키가 없고, 순위·수급·지수 API는 모의투자 도메인에서 지원되지 않는 경우가 많음. 주문 API는 사용하지 않음.
4. **대회 계좌는 수동 매매일지** — 모의 키가 없어 계좌 연동 불가. 매매일지가 유일한 입력이며, 여기서 보유·NAV·성과가 모두 계산됨.
5. **분석은 PQ에서 자체 완결, 결합은 Excel 수식** — Excel은 새로 고침 중 쿼리 간 캐시를 공유하지 않고, 적재된 표를 다른 쿼리가 읽으면 직전 결과(한 박자 늦은 값)를 보므로(실험 3.2), API를 부르는 쿼리끼리 참조하지 않도록 설계.

## 4. 발생한 오류와 해결

### 4.1 핵심 이슈

**① [모두 새로 고침] 테스트가 끝나지 않음 (세션 중단 전후로 이어진 이슈)**
- 증상: 백그라운드 새로 고침 테스트가 15분 넘게 종료되지 않음. Excel 프로세스 CPU만 계속 증가, PQ 컨테이너는 유휴.
- 조사:
  1. 가설 A — 토큰 쿼리의 30분 주기 새로 고침(RefreshPeriod)이 '대기 중 쿼리'로 잡힘 → 주기 있음/없음 두 경우 모두 즉시 반환해 **기각**.
  2. 폴링 방식 진단 스크립트로 같은 새로 고침을 다시 실행 → **15개 쿼리가 32초에 정상 완료**.
- 결론: 테스트 스크립트가 호출한 `Application.CalculateUntilAsyncQueriesDone`이 메인 스레드를 막고, 통합문서 표를 읽는 쿼리(`Excel.CurrentWorkbook`)는 메인 스레드 응답을 기다리는 교착으로 판단. 대화형 사용에는 해당 없음.
- 조치: 모든 검증을 `QueryTable.Refreshing` 폴링 방식으로 변경. README에 "VBA 자동화 시 이 함수 사용 금지" 명시.

**② 실패 시 새로 고침이 몇 분씩 걸림**
- 증상: 설정 파일 경로를 일부러 틀리게 한 테스트에서 시세판 쿼리가 200초 넘게 계속됨.
- 원인: `fnKisGet`이 설정·토큰 오류까지 '네트워크 오류'로 처리해 호출마다 5회 재시도(총 12.4초) × 18종목 × 2호출.
- 해결: 설정·토큰을 재시도 루프 밖에서 먼저 평가해 즉시 실패. 호출 제한(`EGW00201`)만 짧은 백오프로 최대 5회, 네트워크 오류는 1회만 재시도 → **9~14초**로 단축.

**③ 행 단위 `try`가 오류를 못 잡음 (M 지연 평가)**
- 증상: 설정 오류인데도 지수 표의 상태가 "OK"이고 값만 비어 있음.
- 원인: `Get` 함수가 반환하는 레코드의 필드는 나중에 평가됨 → API 오류가 `try` 바깥(표 적재 시점)에서 발생.
- 해결: 반환 전에 응답을 강제 평가(`if not (o is record) then error …`). 표·목록을 반환하는 호출은 `Table.Buffer`·`List.Buffer`로 감쌈.

**④ 조회 실패가 정상 데이터를 덮어씀**
- 증상: 전부 실패하면 오류 행만 남아 시장 화면이 "-"로 비워짐.
- 해결: `fnFallback` 도입 — 모든 적재 쿼리 마지막 단계를 `try Table.Buffer(Main)`로 감싸 실패 시 **직전 결과를 유지**하고 `상태`에 `이전 데이터(갱신 실패: 사유)` 기록. 항목이 **전부** 실패하면 오류로 올려 이 경로로 보내고, 일부만 실패하면 그 행만 오류로 표시. 대시보드 머리글이 이를 집계해 경고.

**⑤ 토큰 동시 발급·알림톡 폭주 위험**
- 원인: 병렬 쿼리들이 같은 토큰 요청을 각각 보냄(실험 3.1).
- 해결: `T_Token` 자기참조 캐시(남은 시간 3시간 미만일 때만 재발급, 발급 실패 시 기존 유효 토큰 유지, 설정 오류도 상태 문자열로 처리). 파일 열 때 + 30분마다 자동 확인.

### 4.2 한국어 Excel · COM 자동화 이슈
| # | 증상 | 원인 | 해결 |
|---|---|---|---|
| ⑥ | `NumberFormat = "[Color10]…"` 설정 실패 | ko-KR Excel은 서식 색 코드도 현지화 요구 | `[색10]`·`[빨강]`으로 자동 변환하는 `set_nf` |
| ⑦ | `NumberFormat = "General"` 실패 | 같은 이유(`G/표준`) | `set_nf` 변환 목록에 추가 |
| ⑧ | `wb.Colors(10, …)` → TypeError | 인덱스 속성이라 pywin32 늦은 바인딩으로 설정 불가 | `Invoke(DISPATCH_PROPERTYPUT)`로 팔레트 설정 |
| ⑨ | 입력 날짜가 하루 앞당겨짐(9/1 → 8/31) | pywin32가 naive datetime을 시간대 변환 | 날짜는 `Value2`에 Excel 일련번호로 입력 |
| ⑩ | 표 이름 `tS1` 지정 실패 | 셀 주소(TS1)와 충돌 | `tbl_` 접두어 |
| ⑪ | LET 수식 입력 실패 | 변수명 `a1`·`b1`·`p1`이 셀 주소 | `al_1`, `pf_1`, `x5_0` 등으로 변경 |
| ⑫ | 조건부 서식 추가 실패/엉뚱한 행에 적용 | 키워드 인수 미동작, 상대참조가 '활성 셀' 기준 | 위치 인수 `(2, 3, 수식)` + 대상 첫 셀 선택 후 추가 |
| ⑬ | 빈 표(0행)에 계산열 수식 입력 불가 | `DataBodyRange`가 None | 임시 행 추가 → 수식·서식 정의 → 저장 전 삭제(실험으로 유지 확인) |
| ⑭ | 입력표 수식 입력 실패 | PQ 표는 첫 새로 고침 전에는 열이 없음 | 새로 고침 후 수식 입력으로 순서 변경 |
| ⑮ | 이름 정의 실패(`주식평가액`) | 아직 없는 계산열 참조 | 이름을 계산열 전/후 두 단계로 정의 |
| ⑯ | 이동 링크가 `대시보드'!A1`처럼 표시 | `TextToDisplay` 무시 + 앞 작은따옴표가 텍스트 접두어로 먹힘 | 셀 값 입력 후 위치 인수로 하이퍼링크 추가 |
| ⑰ | 종목 차트의 가격선이 바닥에 붙음 | 첫 계열을 보조축으로 지정하면 무시되고 모두 주축으로 | 가격 계열 먼저, 거래량은 마지막에 보조축 |
| ⑱ | 선 차트가 빈 칸을 0으로 그림 | 기본 빈 셀 처리 | `DisplayBlanksAs = xlNotPlotted` |
| ⑲ | 숨김 도우미 열 데이터가 차트에 안 나옴 | 기본값이 '표시된 셀만' | `PlotVisibleOnly = False` |
| ⑳ | 시트 배경색이 표 스타일을 덮음 | 셀 서식이 표 스타일보다 우선 | 배경은 보고서형 시트에만, 사용자 표 스타일 `PM Navy` 추가 |
| ㉑ | Quit 후에도 숨김 Excel이 남음 | COM 참조 잔존 | `quit_excel`: 자기 PID만 확인 후 종료. 남은 테스트 인스턴스는 PID·시작 시각 확인 후 개별 종료 |
| ㉒ | 폴링 중 `RPC_E_CALL_REJECTED` | 새로 고침 중 Excel 바쁨 | 바쁨으로 간주하고 재시도 |
| ㉓ | 종목코드 칸의 '텍스트 숫자' 초록 삼각형 | 코드 선행 0 유지를 위한 텍스트 서식 | 기존 셀에만 `Errors(3).Ignore`(범위 단위는 COM 미지원) |

## 5. 보안 관련 사건

- **설정 파일 값 노출**: 초반에 설정 키 존재 여부를 확인하는 명령이 따옴표로 감싼 값만 가리도록 되어 있었는데, `~/KIS/config/kis_devlp.yaml`의 값에 따옴표가 없어 **앱키·앱시크릿·HTS ID가 세션 도구 출력에 그대로 찍혔습니다**. 외부 서비스로 보내지는 않았습니다.
  - 권장: 우려되면 KIS Developers에서 앱시크릿 재발급 후 `kis_devlp.yaml` 갱신.
  - 이후 조치: 비밀 값은 길이·형식만 확인하고 값 자체는 절대 출력하지 않도록 변경. 최종 `.xlsx`에 앱키·시크릿·계좌번호·HTS ID가 **포함되지 않음을 파일 내부 검사로 확인**.
- **토큰 발급 알림톡**: 개발 중 여러 차례 토큰을 요청해 알림톡이 여러 건 발송됐을 수 있습니다(모두 같은 토큰). 현재는 캐시 재사용으로 남은 시간 3시간 미만일 때만 발급합니다.
- **통합문서의 토큰 캐시**: 숨김 시트 `_sys`의 `tblToken`에 24시간 토큰이 저장됩니다. `excel_dashboard/.gitignore`로 `.xlsx`를 커밋에서 제외했고, 외부 공유 전에는 이 표 내용을 지워야 합니다.

## 8. 남은 주의사항과 후속 과제

**대회 전에 할 일**
1. [매매일지]의 `[샘플]` 13행, [설정]의 샘플 관심종목 삭제(현재 수치는 9/1 시작 샘플 포트폴리오).
2. [설정]의 대회 시작일·종료일·초기자금·벤치마크, 수수료율(기본 0.015%)·거래세율(기본 0.20%)을 대회 규정대로 수정.
3. 휴장일 목록은 추정치이므로 KRX 공지로 확인.

**한계**
- 대회 계좌 자동 연동 없음(모의 키 미설정). 대회가 한국투자증권 모의투자 계좌라면 잔고조회(VTTC8434R)·일별체결(VTTC0081R) 연동 추가 가능.
- 첫 실행·토큰 재발급 직후에는 [모두 새로 고침]을 한 번 더 해야 할 수 있음(토큰이 새로 채워지기 전 쿼리가 먼저 돌 수 있음).
- 관심·보유 종목이 늘면 호출 수가 늘어(종목당 약 4회) 새로 고침이 느려짐.
- 대화형 Excel에서의 첫 실행 보안 경고·'웹 콘텐츠 액세스' 창은 자동화 환경에서 재현되지 않아 직접 확인하지 못함(가이드에 대응 방법 기재).
